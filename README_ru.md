# uz801-display

OpenWrt для мобильных роутеров на MSM8916 (MF601SL / UZ801 v3.0 / Xunyou D623 /
UFI103) **с работающим штатным экраном** — плюс дашборд состояния, QR-код для
подключения к Wi-Fi и управление модемом из браузера.

Это автономные устройства с батареей и SPI-экраном 128×128, а не USB-свистки.
Экран нигде не документирован, и ни одно дерево устройств из upstream его не
включает — вся распиновка здесь снята со штатного андроидного девайстри самого
устройства.

[English version](README.md)

## Что работает

* **Экран** — панель 128×128 по SPI, подсветка, вывод консоли ядра при загрузке
* **Дашборд** — оператор, тип сети, уровень сигнала, SSID, IP, число клиентов,
  заряд батареи, скорость
* **QR-код** с именем сети и паролем по двойному нажатию кнопки
* **Свой логотип** при загрузке
* **LTE**, точка доступа Wi-Fi, сеть по USB
* **Управление модемом из браузера** — режим сети, диапазоны LTE, APN, поиск
  операторов с выбором в один клик и автоматический откат, если модем не
  зарегистрировался

## Установка

Скачайте `boot.img` и `system.img` из [Releases](../../releases), переведите
устройство в режим EDL (зажать Reset и, удерживая, подключить USB — появится
`05c6:9008`), затем:

```sh
edl w boot   openwrt-msm89xx-msm8916-yiming-uz801v3-squashfs-boot.img
edl w rootfs openwrt-msm89xx-msm8916-yiming-uz801v3-squashfs-system.img
edl reset
```

Пишутся только разделы `boot` и `rootfs`. Таблица разделов, загрузчики и
радиоразделы (IMEI, калибровка) не трогаются.

> Команду `edl reset` надо давать **без** ключа `--memory=eMMC`. С ним она
> разбирается неправильно, и устройство не перезагружается.

После прошивки Wi-Fi поднимается сам (SSID `OpenWrt`, без пароля — поменяйте),
сеть по USB тоже. APN пропишите в **Network → Modem**.

**Сначала сделайте резервную копию.** Снимите дамп всех разделов через EDL,
особенно `modem`, `modemst1`, `modemst2`, `fsg`, `fsc` и `persist` — в них
лежат IMEI и калибровка радиочасти, восстановить их иначе неоткуда.

## Питание

С работающей подсветкой устройство потребляет заметно больше. Без батареи, от
слабого USB-порта, оно уходит в перезагрузку; со штатной батареей работает
стабильно.

Когда устройство выключено и питается от батареи, включается оно **длительным
удержанием** кнопки — это поведение контроллера питания, а не прошивки.

## Почему экран не работал ни в одной прошивке

Четыре независимые причины, каждая из которых по отдельности даёт чёрный экран.

### 1. Это не ST7735, хотя так подписано

В штатном девайстри панель называется `st7735s`. Но её init-последовательность
начинается с команд `0xFE 0xEF` (inter-register enable) и использует `0xEB`,
`0xE8`, `0xE9`, `0xC6`, `0xC7` — регистров, которых у ST7735 нет вовсе. Это
набор контроллеров GalaxyCore GC9xxx.

Драйвер `fb_st7735r` шлёт команды, которых контроллер не понимает, и панель
остаётся белой. Причём без `0xFE`/`0xEF` контроллер игнорирует **всю**
последующую настройку — именно этих двух команд не хватало и в готовом
драйвере GC9107, найденном в чужих репозиториях.

В `patches/901-fbtft-fb_gc9107.patch` лежит драйвер GC9107, у которого
`init_display()` — это дословно заводская последовательность.

### 2. Chip select припаркован в единице

В mainline вывод GPIO10 — это chip select шины `blsp_spi3` — замультиплексирован
как обычный GPIO и выставлен в высокий уровень, поэтому контроллер SPI не может
им управлять. Панель никогда не выбирается: тактовые импульсы идут, данные
идут, а чип их не слушает.

Драйвер `spi-qup` умеет управлять CS через GPIO (`use_gpio_descriptors`), так
что лечится одной строкой:

```dts
cs-gpios = <&tlmm 10 GPIO_ACTIVE_LOW>;
```

Этот пункт долго маскировал первый: до панели вообще ничего не доходило, и
никакая работа с драйвером не могла дать видимого результата.

### 3. Подсветка — токовый сток, а не GPIO

Подсветка висит на выводе **MPP4** микросхемы питания PM8916 и в заводской
прошивке настроена как токовый сток (`MODE_CTL = 0x60`, режим `110`) с током
10 мА. Объявленная логическим выходом, она лишь коротко вспыхивает при смене
уровня — экран моргает и гаснет. Нужен режим `function = "sink"`.

### 4. Драйвер молча не собирается

У `CONFIG_FB_TFT` жёсткая зависимость `depends on FB_DEVICE`. Без
`CONFIG_FB_DEVICE=y` kconfig выбрасывает драйвер целиком, **сборка проходит без
единой ошибки**, и получается прошивка вообще без поддержки экрана. Поймать это
можно только проверкой `System.map`.

### Распиновка

Из штатного андроидного DTB (`qcom,board-id = <0x8 0x100>`):

| что | значение |
|---|---|
| шина SPI | `spi@78b7000` = `blsp_spi3` (`aliases { spi0 = … }`) |
| chip select | GPIO 10 |
| данные/команда (DC) | GPIO 23 |
| сброс (RESET) | GPIO 25 |
| питание панели | `pm8916_l17` (2.85 В) |
| питание ввода-вывода | `pm8916_l6` (1.8 В) |
| подсветка | PM8916 MPP4, токовый сток |

Файл `msm8916-yiming-uz801v3.dts` из upstream описывает **другую плату**: там
кнопка Restart висит на GPIO23 (это DC нашей панели), а зелёный светодиод — на
GPIO8 (это MOSI шины `blsp_spi3`). Оба узла удалены в `patches/806-*.patch`.

## Модем не работает с ModemManager

ModemManager оставляет модем в состоянии `offline` и отклоняет любую попытку
включить радио (`InvalidTransition`), рапортуя при этом `sim-missing` — хотя
`--uim-get-card-status` показывает карту как `present` и `ready`, и IMSI
читается без проблем. То же самое описано в вики postmarketOS для этого
устройства.

Поэтому ModemManager здесь нет вообще. Соединение поднимает **zhihe-qmi** —
обработчик протокола netifd, работающий напрямую через `qmicli` (взят из
[ImMALWARE/uz801-openwrt](https://github.com/ImMALWARE/uz801-openwrt)) с двумя
исправлениями:

* **Маска подсети.** Сравнивалась со списком из трёх значений, поэтому `/28`
  (а этот оператор выдаёт именно её) молча превращалась в `/32`, и шлюз
  становился недостижим. Теперь длина префикса считается из любой маски.
* **Параметр `device`.** Был объявлен как `"device:device"`, из-за чего netifd
  и LuCI трактуют его как *имя сетевого интерфейса*: достаточно один раз
  сохранить страницу интерфейса в браузере, чтобы путь `/dev/wwan0qmi0`
  подменился на `wwan0` и связь пропала. Коварно тем, что ломается не сразу, а
  после совершенно безобидного действия. Теперь это обычная строка, и протокол
  отвергает всё, что не является символьным устройством.

Выбор оператора идёт через `AT+COPS`, а не через QMI: на эту прошивку QMI-аналог
отвечает голым `Internal error`. Работает только при опущенной передаче данных
— поэтому любое применение настроек сначала опускает интерфейс.

## Один владелец канала QMI

Дашборд на экране, страница информации и страница управления читают данные
через **один** сервис ubus (`modem-control`). Больше никто не вызывает
`qmicli`, поэтому конфликтовать за канал некому, а минутный поиск операторов не
подвешивает экран — читатели получают значения из кэша вместе с флагом
занятости.

```
   дашборд на экране ─┐
   Cellular Info    ──┼──►  ubus modem  ──►  qmicli  ──►  модем
   управление модемом ┘        + кэш
```

Применение настроек выполняется **в фоне**: rpcd обрывает вызовы, которые не
уложились в его таймаут, и раньше прерванное применение оставляло модем
наполовину настроенным, а флаг занятости — навсегда взведённым, из-за чего все
кнопки в интерфейсе оставались заблокированными до перезагрузки. Теперь флаг
несёт метку времени и протухает сам, а неудачная регистрация возвращает прежние
режим, диапазоны **и оператора**.

## Пакеты

| пакет | что делает |
|---|---|
| `router-display` | отрисовка (текст через FreeType, векторные виджеты, QR), демон с таймерами затухания и гашения, обработчик кнопки, логотип загрузки |
| `zhihe-qmi` | протокол netifd для LTE-соединения и его страница в LuCI |
| `modem-control` | сервис ubus и страница **Network → Modem** |
| `luci-app-cellular-info` | сигнал, информация о соте и соседних сотах |

Правки вёрстки не требуют перепрошивки: пересоберите `router-display`,
скопируйте бинарник в `/usr/bin/router-display` по сети и запустите
`update-display`.

## Сборка

Собирается поверх
[hkfuertes/msm8916-openwrt](https://github.com/hkfuertes/msm8916-openwrt) —
именно оттуда происходят заведомо рабочие образы для этих устройств.

В CI это делается автоматически, см. `.github/workflows/build.yml`: он кэширует
скачанные исходники, тулчейн и ccache, поэтому повторные сборки идут заметно
быстрее первой. Вручную:

```sh
git clone https://github.com/hkfuertes/msm8916-openwrt upstream
git clone --depth 1 -b v25.12.5 https://git.openwrt.org/openwrt/openwrt.git openwrt

cd upstream
./apply_patches.sh ../openwrt
cp -r msm89xx  ../openwrt/target/linux/msm89xx
cp -r packages ../openwrt/package/msm8916
cd ..

cp patches/*.patch  openwrt/target/linux/msm89xx/patches/
cp -r package/*     openwrt/package/msm8916/
cat config/kernel-additions.txt >> openwrt/target/linux/msm89xx/config-6.12

cd openwrt
./scripts/feeds update -a && ./scripts/feeds install -a
cp ../config/diffconfig_uz801 .config
make defconfig
make -j$(nproc)
```

Результат появится в `bin/targets/msm89xx/msm8916/`.

Проверяйте, что девайстри компилируется, **до** запуска полной сборки —
опечатка в нём это самый частый способ потерять сорок минут:

```sh
make target/linux/prepare
```
